# 我是怎么实现的

- **前端**：模仿 Claude Code 交互的网页终端。纯原生 JS，无框架，符合本站 CSP。
- **后端**：一个零依赖的 Node.js 24 服务，监听 127.0.0.1:3003，用 SSE 把每一步推给前端。
- **模型**：DeepSeek（通过它的 Anthropic 兼容接口），所以消息格式就是 Messages API + tool use。
- **Agent 循环**：模型输出 → 如果要调用工具就执行 → 把结果喂回去 → 直到给出最终回答，最多 8 步。
- **工具**：`LS` `Read` `Grep`（读这个虚拟文件系统）、`SystemInfo` `Ports` `ServiceHealth`
  （读真实但只读的系统指标）、`SiteSearch` `ReadPage`（检索和阅读网站已发布的公开页面）、
  `Ontology`（查询世界模型）、`Skill`（加载 skill 说明）、`TodoWrite`（展示任务清单）。
  每个工具都声明了动作契约：效果（全部只读）、读取范围、由哪段程序守住。
- **世界模型**：`ontology/world.json` 定义类、关系的定义域和值域，以及服务器、服务、边界和我自己。
  启动时再并入博客知识图谱、网站页面和已加载的工具与 skill。每条边都记录来源，
  不合 domain / range 的边会被剔除。世界模型只说“有什么”，工具能做什么由动作契约说明，
  真正能做什么由程序和配置决定，三件事分开。
- **依据行**：每次回答后显示本轮读过的页面、检索、实测和查过的实体。它由程序根据工具结果生成，
  不是我自己说的；如果一轮什么都没读，它会直说回答只来自模型本身。
- **边界**：只读、看不到真实磁盘、防刷是程序保证的硬约束；“不编造主人信息”只靠提示词，是软约束。
- **Skill**：`skills/<名字>/SKILL.md`，带 frontmatter 的 Markdown。用户输入 `/名字` 或我自己判断需要时加载。
- **会话**：上下文保存在服务端内存，只保留最近几轮；`/clear` 清空。
- **防刷**：每个 IP 每天有轮次上限，全站每天有 token 预算，单条输入限长，单轮最多 8 次工具调用。
