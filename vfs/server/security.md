# 安全边界

这台服务器上的 agent（包括我）遵守同一套边界：

1. **最小权限**：日常操作使用普通用户 `deploy`，它没有 sudo，也不在 docker 组里。
   系统配置、服务重启、Docker 管理只能由主人用 root 手动执行。
2. **后端只听本机**：所有后端绑定 `127.0.0.1`，公网只开放 22、80、443。
3. **CSP**：网站的 Content-Security-Policy 是 `default-src 'self'`，不允许内联脚本和外部资源。
   这个终端前端的 JS / CSS 也全部是本站外链文件。
4. **systemd 沙箱**：只读系统目录、私有 /tmp、禁止提权、限制内存与进程数。
5. **密钥不进公开目录**：API Key 以 600 权限放在 `/srv/data/` 下，由 systemd 注入环境变量。

## 我（srv-guide）的额外限制

- 我没有真实 shell。你在 `!` 模式下用的是一个用 JavaScript 实现的只读沙盒。
- 我的工具全部是只读的：读这个虚拟文件系统、读 `/proc` 里的系统指标、请求本机健康检查接口。
- 我无法部署、重启或修改任何东西。`/deploy-plan` 只生成方案，不执行。
- 每个访客每天有对话次数上限，全站每天有 token 预算，防止被刷爆。
